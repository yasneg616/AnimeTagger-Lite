# 离线语义随机 Prompt

随机页默认使用语义生成，也可切换回原分类抽词。两种模式共用本地模型的 CSV 词表，不需要加载推理模型。

语义模式先记录画面中的主体、各自的外观和服装、动作、持有的道具、互动参与者、环境与构图，再生成 Tags 和 English。切换页签保留同一份画面。默认一个原创主体、普通内容、自然自由度、标准细节。

可以生成 1–4 个主体，选择已有角色、主题、地点、动作、内容等级和细节量。在 A1–A4 的固定属性中填写 tags，或锁定已有主体及画面后重新随机。失败时显示冲突或缺少的依赖，并保留上一份结果。所有候选扩展共享 2,000 次上限。

已有角色使用身份档案中的外观；年龄未知或未成年角色只进入普通内容。成人模式的所有主体须确定成年。自由度只调整搭配偏好，属性互斥和年龄约束始终生效。

外部输入首版接受 tags。人数标签可自动识别，也可指定 1–4 人。括号、权重、重复项及未知词保留在 Tags 原文中；未知或尚未核对规则的词不会被补写成英文事实。多人外观先分配主体，持有动作需要分配道具所有者；方向性互动选择施动者和接收者，三人以上的对称互动选择参与者。冲突解决后生成英文。生成输出中的字面括号会转义，避免表情 tag 被误读为权重语法。

已有角色保持确认的外观和默认服装。默认服装资料不足时不自动编造一套服装；动作也不能凭空补出未确认的身体属性。角色的颜色、身体特征和服装默认值分别记录。无一致依据的版本差异保留为待核对。

通用平铺 tags 的表达能力有限。例如两个人分别红发和蓝发，平铺后缺少发色归属；英文和画面摘要保留这些信息。编辑输出文本不会修改已保存的画面属性。

词库与规则在 `resources/prompt_semantics/`。运行时只读整理资源和本地 CSV，采集程序独立运行。

```powershell
# 限速采集公开 Wiki、有效别名及包含关系；自动缓存、重试和续采。
.venv311-cuda\Scripts\python.exe scripts/fetch_prompt_semantics.py
# 补采官方分组，用于后续资料核对；分组归属本身不会使条目进入随机池。
.venv311-cuda\Scripts\python.exe scripts/fetch_prompt_semantics.py --groups-only
# 读取 Wiki 指定的默认外观参考，仅采集官方图片的标签和来源元数据。
.venv311-cuda\Scripts\python.exe scripts/fetch_character_references.py
# 从缓存重新编译。门槛未达到时 --require-coverage 返回非零。
.venv311-cuda\Scripts\python.exe scripts/build_prompt_semantics.py --require-coverage
# 按频率导出逐条候选资料、来源证据和空白核对模板；草稿不会进入运行时词库。
.venv311-cuda\Scripts\python.exe scripts/export_prompt_semantics_review.py
# 全离线分布审计。
.venv311-cuda\Scripts\python.exe scripts/validate_prompt_semantics.py --seeds 10000
# 输出分类覆盖、剩余缺口与代表画面。
.venv311-cuda\Scripts\python.exe scripts/report_prompt_semantics.py
```

资料来源：[Wiki API](https://safebooru.donmai.us/wiki_pages/api:wiki_pages)、[别名 API](https://safebooru.donmai.us/wiki_pages/api:tag_aliases)、[包含关系 API](https://safebooru.donmai.us/wiki_pages/api:tag_implications)。每个登记条目保留来源链接、源更新时间、内容摘要哈希和核对状态。Wiki 正文留在构建缓存，发布包只含整理数据。

## 规则族与证据边界

除含义、属性构造与动作依赖外，编译器还按正面定义识别以下规则族。每族都要求条目自身 Wiki 的引言给出正面定义，并把该段作为 `rule_evidence` 保留；只有来源正文、分组或旧释义的条目不会因此变为可用。

- **`species_feature_trait`**（`scripts/prompt_semantic_species.py`）：定义形如「A girl with bat features」时，主体被表述为**具有**某物种的身体特征，映射到 `body.species`，不产生道具依赖，也不附带任何年龄判断。定义中的物种还须与词条自身匹配；未知物种或与名称相反的定义不会通过。若条目只说明主体**就是**该生物（例如「A female ghost」）、或物种用「or」并列而不确定，则保留在待核对队列。物种词还须已由本词库的其他规则表达，散句无法凭空引入新特征。`conditions` 中的性别来自定义用词，`original_only` 表示只作用于原创主体。
- **`absent_attribute`**（`scripts/prompt_semantic_negation.py`）：定义须明确说明指定物品缺失；「没有兜帽的披风」不能解释成没有披风。具体物品只排除该物品，不能把整个外套槽或身体细节槽禁用，特征记为 `absent.item.<item>`。若定义指某角色通常拥有的默认属性或身份变化，则还需要原有身份和版本参照，暂不计入可用。衣物类缺失要求另有已穿着的衣物才成立，身体特征类缺失不需要。`scripts/prompt_semantic_supplement.py` 中手写的 `no shoes` / `no panties` 等保持原有语义、前置条件与内容等级，编译顺序上先于本族。
- **手持物可及性**：`holding <object>` 依赖物体规则可被手持。当物体自身的 Wiki 未提手部、但其 `holding_` 条目的定义明确描述手持动作（乐器、打蛋器、棉花糖等）时，该物体登记为可手持；生物类名词（animal、bird、creature）刻意不做可手持处理。手工具类（撬棍、鼓槌、打火机、拖把、记事本、球拍、牙刷）按各自正文定义为object，其 `holding_` 动作随之可解析到有归属的道具。
- **身体部位印记**：`scar_on_<part>` 等正文为「located on a person's <part>」的条目登记为 `body.detail`，与既有的 `scar on face` 同类，不牵涉其他主体或持有物。
- **具体概念**（`scripts/prompt_semantic_concepts.py`）：按已核对的名称与自身引言定义建立物品、服装、表情和小动作规则。兜帽状态需要同一主体实际穿着带帽服装；嘴衔、跨坐等动作需要有所有者的道具；服装拉动需要实际服装。正文后段的例子不能替代不匹配的引言定义。
- **可见文字与人数**：年份条目采用正文明确允许的「画面中写出的年份」，不推断创作日期或场景时间。`1other`–`4others` 表示性别未确定的人形主体，导入与校验按实际人数核对。
- **颜色与关系**：毛皮和鳞片可有多种颜色的区域；已有身份仍锁定来源中的配色。父母子女等关系要求分配有方向的参与者，仅用于原创普通画面，不推断后代年龄，也不替已有角色编造家系。

缺失类规则不带独立年龄含义：`adult` 沿用被排除物品自身的分类，也不会新增 `age:` 条件。`article()` 对 `no `/`without `/`missing ` 开头的短语不再追加冠词，因此渲染为「no cape」而不是「a no cape」。

`coverage.json` 提供分类统计，`coverage.tsv` 提供逐条状态与缺口。可用规则来自明确含义、属性构造、动作依赖及受控表达的整理；已有正文或旧中文释义不直接计为可用。规则通过也可能存在尚未建模的语义问题，代表画面仍需人工审阅。

剩余 **5,124 条**包括 4,948 条候选、110 条只有词义的条目和 66 条缺 Wiki 的条目（另有 428 条已登记中性识别资料，见上）。待核对资料导出批次位于构建缓存 `data/prompt-semantics/review/56999030cce745b3/`；旧批次保留。逐项缺口与新增、撤回记录见 `validation/semantic-isolated/` 中的 `未完成词条.tsv`、`词条变更.json` 和 `词库覆盖与缺口.txt`。这些资料继续保留，未混入可用随机池。角色正文中的其他角色、不同版本和不确定年龄不能作为固定身份或年龄证据。

本轮角色档案总数为 2,776 份，`age_state` 为 10 份 `adult`、13 份 `minor`、2,753 份 `unknown`；成人内容可选身份仍只有 9 个，年龄判定未放宽。缺口主要是尚未实现的定义规则族、动作或位置依赖，以及角色默认外观参考不足；不能全部归因于内容审查。后续应逐项补证据和结构规则，不应为凑数增加通配放行。

## 已知限制（合并后验收记录）

2026-10-11 合并后的独立验收（`validation/final-acceptance/`）确认两点既有行为，未在本轮改动：

1. **反斜杠表情词条无法无损往返**。CSV 中 6 个词条含反斜杠，其中 `\||/` 与 `double \m/` 有可用规则。输出会把反斜杠转义为 `\\`，以阻止下游把转义符当作控制字符；重新导入同一文本时该词条按未知词处理（保留原文与权重、提示未核对、不补写英文事实，tags 输出逐字不变）。影响 2 条规则，属于标签语法与「保留原文」之间的既有取舍。
2. **扁平 tags 往返不保留道具归属**。双主体画面生成的道具在 tags 中只是一个词条；导入时若 `holding` 的候选物体（3,679 个）中恰有同名可穿戴词条，该词条会被判为穿戴而非持有，从而报告一次槽位冲突与一次依赖缺失。单主体画面的 `holding_weapon` 也会因词表实际拼写为 `holding_weapon` 而无法在导入时确认持有关系。生成路径不受影响（1,200 组抽样 0 次该错误），导入路径会如实报告冲突并保留原文。
