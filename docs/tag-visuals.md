# 标签图示与中文释义（1.3.0）

## 界面

单图标签表保留六列和原英文编辑内容，在标签列显示 24×24 彩色图示。
随机 Prompt 的抽中标签使用只读图标列表，支持多选和 Ctrl+C 复制原英文行。
两处列表共用 160×160 悬停卡，显示英文、简体中文短释义、图示类型及原有来源信息。
修改标签立即更新图示；滚动、切图、切换页面、模型重置、修改标签和关闭开关都会关闭旧卡片。

“筛选与显示 → 图示辅助”默认开启。`QSettings` 的 `tag_visuals/enabled` 保存开关；
便携版沿用原程序的 `data/config/ui.ini`。中文搜索使用已有释义，图示分类独立于 Prompt 分组。
原图、模型结果、英文标签、Prompt、复制、TXT/JSON 和 CLI 不写入图示数据。

## 覆盖边界

三个模型的 12,030 个一般标签、4 种 Rating、PixAI `ip` 中的作品名称、
项目预设词和已整理的手动词都进入逐项清单。同名的一般标签和角色标签按类别区分，
角色名称统一标记 `excluded_character`。新增未知标签在线下已有规则范围内匹配。

| 范围 | 具体图示 | 组合图示 | 辅助示意 | 类别提示 | 待补 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 模型一般标签（12,030） | 1,165 | 1,993 | 121 | 76 | 8,675 |
| 全部非角色条目（12,710） | 1,200 | 1,993 | 148 | 690 | 8,679 |

一般标签的含义图示共 3,279 个，前 1,000 个高频标签中覆盖 951 个（95.1%）。
高频排序取三个 CSV 的最大 `count`，同频用规范化键排序；63 个零频词和一个负频词仍保留在全量清单中。
`category_only` 不计入含义覆盖率，剩余高频缺口逐项记录于 `coverage.json`。
长尾并未全部完成图示与释义；未核对、专有名词和难以准确简化的标签注明理由，避免用通用图标冒充具体含义。

头发、眼睛、面部、表情与视线、身体特征、服装配饰、姿势动作、人物互动、主体物品、
场景天气、构图、光照、画风特效、文字标记和评级均有代表图示。
库中有 1,427 个词义定义和 278 个原创基础形状。颜色词保持发色、瞳色、服装颜色的含义，
主题只调整轮廓和中性背景。复杂概念使用箭头、多人场景、局部框或画面布局说明。

## 数据与维护

输入与生成文件在 `resources/tag_visuals/`，阅读入口为
[资源说明](../resources/tag_visuals/README.md)。
中文释义为人工整理的项目说明；术语分类依据 Danbooru 官方词条分组。
有明确核对来源的词条在 TSV 的 `reference` 列记录链接，其余标记为项目定义或已知词组合。
SVG 全部由本项目原创，按项目 MIT 许可分发，没有下载或复制标签示例图片。

开发环境中更新 TSV 后运行：

```powershell
.venv311-cuda\Scripts\python.exe scripts\build_tag_visuals.py
.venv311-cuda\Scripts\python.exe -m pytest tests/test_tag_visuals.py tests/ui/test_tag_visuals.py -q
```

生成器读取三个 `models/*/selected_tags.csv`、Prompt Profile 与负向预设，合并规范化标签；
记录来源、最大频次、定义文件哈希、每项状态及待补原因。它不读取用户配置或图片，运行时不调用生成器。
名称规范化复用 `canonical_tag_key`，匹配键包含类别；组合规则只消费已知的完整中心词及有限修饰词。
从零重建规则与目录，不依赖旧 `catalog.json`，便于复核覆盖统计。

`app/tag_visuals.py` 无 Qt 依赖，提供 `lookup(name, category)`；
不可变描述包含图示配方、简体中文说明、独立分组和状态。
`app/tag_visual_svg.py` 根据描述生成 SVG，小图和大图共用配方，大图可增加定位辅助线。
`app/ui/tag_visual_widgets.py` 共用渲染、缓存和悬停组件。Qt SVG 按需渲染，
小图缓存最多 512 个，大图最多 32 个；名称、类别、主题、尺寸和 DPR 都参与缓存键。
资源加载失败或 SVG 损坏只限制显示，原标签及推理仍可使用，错误写入现有日志。

## 验证入口

新增测试覆盖规范化、类别冲突、未知/手动词、损坏资源、共享开关与持久化、
编辑更新、悬停失效、中文搜索、只读列表、缓存上限及 Prompt/TXT/JSON 一致性。

显式诊断模式使用隔离配置，不加载模型，不修改用户偏好。源码示例：

```powershell
.venv311-cuda\Scripts\python.exe -m app.ui --visual-smoke validation/tag-visuals/source-100
```

便携版同样接受 `AnimeTaggerLite.exe --visual-smoke <输出目录>`。
诊断模式保存五种主题的实际窗口、悬停卡、48 个固定样例及 42 个长尾样例，
验证完整可渲染目录、关键差异、开关、编辑和大量标签滚动。
`visual-smoke.json` 记录实际 DPR、Qt 平台、源码/冻结标志、检查结果及截图哈希。
缩放需查看报告的实际 DPR，不能只根据环境变量判断。

本次源码与便携版的五主题、100%/150%/200% 显示验证、完整测试与构建结果见
[验收记录](../validation/tag-visuals/ACCEPTANCE.md)。图示诊断的标签为固定样例；真实模型推理另行验证。
